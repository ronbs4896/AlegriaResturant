# מערכת חשבוניות — קייטרינג אלגריה

מערכת פנימית לאיסוף מסמכי הוצאה: קליטה אוטומטית מהמייל, צילום קבלות
מהטלפון, וייצוא חודשי מסודר לרואה החשבון.

**זו לא מערכת ציבורית.** אין קישור אליה מאתר השיווק, היא חסומה לרובוטים,
וכניסה אליה מוגבלת לרשימת כתובות מאושרת.

## איפה זה יושב

התיקייה הזו היא פרויקט נפרד בתוך ה-repo של אתר השיווק. שני הפרויקטים
לא חולקים קוד, תלויות או בנייה: האתר הוא Vite בשורש, וזו אפליקציית
Next.js שכל מה שנוגע לה נמצא כאן, כולל `package.json` משלה.

ב-Vercel הם שני פרויקטים נפרדים מאותו repo, ונבדלים ב-Root Directory:
האתר על `.` ועולה ל-`www.alegriacatering.co.il`, המערכת על `books`
ועולה לתת-דומיין נפרד. תת-דומיין ולא נתיב, כדי שעוגיית ההתחברות לא
תשב על הדומיין הציבורי.

## הרצה מקומית

```bash
cd books
npm install
cp .env.example .env.local     # ערכו לפי ההסבר בקובץ
npm run dev                    # http://localhost:3000
```

**אין צורך בחשבון, במסד או בטוקן כדי להריץ מקומית.** בלי `DATABASE_URL`
המערכת מרימה PGlite — Postgres שרץ בתוך התהליך — ובלי
`BLOB_READ_WRITE_TOKEN` היא כותבת קבצים ל-`.storage/`. בלי
`RESEND_API_KEY` קוד ההתחברות מוצג על המסך במקום להישלח במייל.

המינימום ההכרחי ב-`.env.local`:

```
SESSION_SECRET=<openssl rand -base64 48>
AUTH_ALLOWLIST=you@alegriacatering.co.il:admin
BUSINESS_TAX_ID=<ח.פ. של אלגריה>
```

`BUSINESS_TAX_ID` הוא לא נתון קוסמטי: הוא מה שמכריע אם מסמך הוא הוצאה
או הכנסה. בלעדיו המערכת לא תסווג כלום לבד.

## מה ההעלאה עושה

1. הדפדפן מקטין את התמונה ל-2000px ודוחס ל-JPEG — צילום של 8MB יוצא
   כ-400KB. הפעולה רצה ב-Web Worker כדי שהמסך לא ייתקע, וכיוון ה-EXIF
   נקרא ומיושר לפני ההקטנה.
2. הקובץ נשמר בנתיב מבוסס-תוכן: `raw/YYYY-MM/<sha256>.<ext>`.
   שתי תוצאות שלא צריך לתכנת בנפרד — אותה קבלה שצולמה פעמיים נספרת
   פעם אחת, ושינוי בייט אחד מייצר נתיב אחר ולכן ניתן לגילוי.
3. נוצרת שורה במסד בסטטוס `pending`, שממתינה לחילוץ (שלב 3).

**מגבלה ידועה:** ההעלאה עוברת דרך פונקציית שרת, שגבול גוף הבקשה שלה
ב-Vercel הוא 4.5MB. אחרי ההקטנה צילומים הם כמה מאות KB, כך שהתקרה
נוגעת רק ל-PDF גדול שמעלים מהמחשב. העלאה ישירה ל-Blob דרך קישור חתום
היא שיפור לשלב 6 — היא מומשה בשכבת האחסון אך לא נבדקה, כי אין עדיין
טוקן Blob אמיתי לבדוק מולו.

## פריסה

1. פרויקט Vercel **חדש** מאותו repo, עם **Root Directory = `books`**.
   האתר נשאר בפרויקט הקיים ולא נוגעים בו.
2. **Vercel Pro** — הרובד החינמי מוגבל לשימוש לא-מסחרי, ורק Pro מאפשר
   cron בתדירות גבוהה מפעם ביום (נדרש לשלב 4).
3. Vercel Blob, **חנות פרטית**. ה-token נכנס ל-`BLOB_READ_WRITE_TOKEN`.
4. Neon Postgres, ואז `npm run db:push` עם `DATABASE_URL`.
5. משתני הסביבה מ-`.env.example`, כולם.
6. תת-דומיין, למשל `books.alegriacatering.co.il`, על הפרויקט הזה בלבד.

כדי ששינוי באתר לא יבנה מחדש את המערכת ולהפך, ב-Settings → Git →
Ignored Build Step של כל פרויקט:

```bash
# פרויקט האתר
git diff HEAD^ HEAD --quiet -- . ':(exclude)books'
# פרויקט המערכת
git diff HEAD^ HEAD --quiet -- books
```

בייצור בלי `DATABASE_URL` המערכת מסרבת לעלות במקום ליפול חזרה לפיתוח.
זו התנהגות מכוונת.

## החלטות שכדאי להכיר

**קוד בן 6 ספרות ולא קישור קסם.** באייפון קישור שנפתח מתוך Gmail או
וואטסאפ נפתח בדפדפן הפנימי של האפליקציה, וה-session נוחת שם — המשתמש
חוזר לספארי ומגלה שהוא עדיין מנותק. קוד לא סובל מזה.

**הסיווג נעשה על המסמך, לא על השולח.** ח.פ. המנפיק מול ח.פ. הנמען.
ספק יכול לשלוח מכתובת Gmail אקראית; ח.פ. במסמך לא משקר. סינון לפי
שולח קיים רק כפילטר מקדים שחוסך קריאות API.

**ולידציה דטרמיניסטית גוברת על החילוץ.** מודל שפה יכול להחזיר סכום שגוי
בביטחון מלא. `net + vat = total`, ספרת ביקורת של ח.פ., ושיעור מע״מ לפי
תאריך המסמך — אלה נבדקים בחשבון ולא בשאלה. `src/lib/validate.ts`.

**כל הקבועים הרגולטוריים מתוארכים.** מסמך מ-2025 נבדק מול הכללים שהיו
בתוקף ב-2025. שיעור המע״מ וסף מספר ההקצאה שניהם השתנו לאחרונה, וחשבונית
ישנה שתיבדק מול הכללים של היום תיפסל בטעות. `src/lib/constants.ts`.

**מספר הקצאה הוא הסעיף ששווה כסף.** מ-1 ביוני 2026 הסף הוא 5,000 ₪ ללא
מע״מ. חשבונית ספק מעל הסף בלי מספר הקצאה תקף אינה מזכה בניכוי מס
תשומות, גם אם היא תקינה לגמרי. המערכת תסמן כל אחת כזו.

- **לא מוחקת ולא משנה מסמכים מקוריים.**

  ניהול פנקסים (נספחים ו׳ ו-ז׳ לסעיף 36) שדורש בין השאר חתימה
  אלקטרונית מאושרת לכל קובץ סרוק. האינדקס כאן בנוי לפי שדות נספח ז׳
  כך שהוא **יכול** לשמש כארכיון תואם, אבל ההחלטה על ביעור המקור היא של
  רואה החשבון שלכם.
- **לא מדווחת לרשויות ולא מגישה PCN874.** מייצרת את השורות; ההגשה שלו.
- **לא מתחברת לבנק ולכרטיסי אשראי.**
